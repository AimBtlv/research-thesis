##  1. How  Assigned Unicode ID and Phonetic Versions?

This step establishes a catalogue that assigns cuneiform sign in the Unicode unique identifier and its full range of phonetic transliteration values.

The goal is to create a single reference table  as the lookup layer for all subsequent corpus parsing. When an ATF text contains a token such as 'sila₃' or lamma(GURUŠ), the pipeline must be able to answer two questions: 
- Which Unicode sign does this token refer to? 
- What is the full set of phonetic values this sign can carry?     
**The first stage of the pipeline is to assign: Unicode ID + Phonetic Version table.**

## Data Sources 

|Source	|Description|	
|----|----|
|**Unicode Cuneiform Block** unicodeSigns.csv|Complete list of 1,235 cuneiform code points (U+12000–U+1254F) as defined by the Unicode Consortium. Each entry carries the code point, the cuneiform glyph, and a plain-text transliteration label derived from the Unicode character name|
|**Syllabary CM** syllabary_CM.txt |Sign list compiled by Professor Massimo Maiocchi. Maps phonetic ATF readings to scientific sign names (e.g. sila₃ → SILA₃). Covers standard cuneiform periods.|
|**Uruk Archaic Syllabary**syllabary_uruk2.txt|Sign list for the proto-cuneiform Uruk IV–III period (3400–3000 BCE). |
|**Additional Signs** additional_signs.txt|Supplementary mapping file for rare, compound, or non-standard sign forms encountered in CDLI corpora that are absent from the main syllabary.|
|**ORACC Sign List** osl.asl|Machine-readable version of the ORACC Sign List (OSL), the current standard scientific catalogue of cuneiform signs. ASL format encodes sign names (@sign), Unicode IDs (@list U+), glyphs (@ucun), and all attested phonetic values (@v).|

## Pipeline Overview 

The pipeline follows a sequential strategy, processing the Unicode sign list in two passes. 
1. The first pass matches signs to the professor's syllabary. 
2. The second pass enriches the remaining unmatched signs from the ORACC Sign List. 

---
Both outputs are merged into a unified table of 1,235 entries

|Stage|	Input|	Output|
|---|---|---|
**Stage A**|unicodeSigns.csv + Syllabary_CM.csv|matched_signs_full.csv (791) + unmatched_for_review.csv (444)|
**Stage B**| unmatched_fro_review.csv(444) + osl.asl|restUnicodeSigns.csv(444): 424 enriched + 19 partial*|
**Stage C**|matched_sign_full.csv(791) + restUnicode.csv(444)|Full catalogue: 1,235 signs|



*19 characters do not have Unicode in osl.asl as individual characters but are part of compound characters in osl.asl

## Step-by-Step Description
### 1.Build the Syllabary (Syllabary_CM.csv)
Three source files were merged into a single, unified syllabary:   
●	**syllabary_CM.txt** the main phonetic mapping compiled by Professor  Massimo Maiocchi.  
●	**syllabary_uruk2.txt** archaic Uruk-period sign names    
●	**additional_signs.txt** supplementary entries for rare or compound forms

Each line in the merged file follows the format: phonetic_reading to SIGN_NAME. 

**Output: Syllabary_CM.csv** acts as the lookup dictionary for Stage A.
### 2.Download and Prepare the Unicode Sign List
The complete list of cuneiform Unicode code points was obtained from the Unicode Consortium's Cuneiform block (U+12000–U+1254F).  
**Link**: https://www.unicode.org/charts/?utm_source=chatgpt.com    
**Resulting** in 1,235 signs. 

**Each record contains:**   
●	**unicode_id** the code point (e.g. U+12000).  
●	**sign_grapheme** the rendered cuneiform character (e.g. 𒀀).   
●	**transliteration** the Unicode character name converted to transliteration form (e.g. "a", "a × bad").   

**Output: unicodeSigns.csv**  
This file becomes the left-hand side of all subsequent joins and defines the target set: every sign in the final catalogue must have a Unicode ID.

### 3.First Join: Unicode List × Syllabary_CM (Stage A)
The Unicode sign list was joined against Syllabary_CM.csv by matching sign names.

The join produces two outputs:    
●	**matched_signs.csv (791 signs)** signs found in both the Unicode list and the syllabary. Each matched sign receives its syllabarySign (scientific name) and PhoneticsVersion (all attested phonetic readings, pipe-separated).    
●	**unmatched_signs.csv (444 signs)** signs present in the Unicode list but absent from Syllabary_CM. These are primarily compound signs, archaic signs, or variant forms whose names were recorded differently in the syllabary.

**Output:**
|Output file|Count|Status after Stage A|
|---|---|---|
|matched_signs.csv|791|Complete unicode_id + phonetic values assigned|
|unmatched_signs.csv|444|Partial  unicode_id only, no phonetic values yet|
|Total|1235|Covers full Unicode cuneiform block|


### 4.Second Join: Unmatched Signs × OSL (Stage B)
The 444 unmatched signs were processed against the ORACC Sign List (osl.asl). The OSL file is structured into @sign blocks, each identified by a @list U+ tag that links the sign to its Unicode code point.    

For each unmatched sign, the parser:   
●	Searched the OSL for a @sign block whose @list U+ matches the sign's unicode_id.   
●	Extracted the scientific sign name from the @sign line to column syllabarySign
●	Collected all @v (phonetic value) entries in that block to column PhoneticsVersion (pipe-separated)

**Output: restUnicodeSigns.csv**.  
|Sign|Count|Description|
|---|---|---|
|Full Matched in OSL |424|-|
|Not found as main @sign in OSL (coded as @form allograph)|19|These signs have a Unicode code point but appear in OSL only as @form (graphic variant) sub-entries inside another @sign block. They are compound or archaic variants whose reading is inherited from the parent sign.|
|Total|444|Phonetic fields left empty where unavailable|


### 5.Merge: Final Catalogue (Stage C)
The two output files from Stages A and B were concatenated into a single unified catalogue:
|Source file|	Records|	Notes|
|---|---|---|
|matched_signs.csv|791|Full phonetic coverage from Syllabary_CM|
|restUnicodeSigns.csv|444|Phonetic coverage from OSL |
|Total|1235|Covers the complete Unicode cuneiform block|

**Output: unicodePhoneticVersion_full.csv**

## Output Description
Total signs in Unicode cuneiform block: 1235 signs.     
The PhoneticsVersion column deliberately records all attested readings for each sign, not only the most common one



All records share the same schema:
- **unicode_id** - Code point in U+XXXXX format. Primary key. Unique per sign. Source: Unicode Consortium
- **sign_grapheme**- Rendered cuneiform character. One character for simple signs, and sequence for compound signs that lack a unified code point. Source: Unicode Consortium
- **unicodeTrLit**- Human-readable transliteration of the Unicode character name. Describes the graphic composition of the sign (e.g. "a × bad" for A×BAD). Source: Unicode Consortium
- **syllabarySign**- Scientific sign name as used in Assyriology (e.g. A, SILA₃, |AN.KI|). Standard identifier used in sign lists and cited in publications.Source: Syllabary_CM / OSL
- **PhoneticsVersion**- All attested phonetic readings of the sign, pipe-separated. Encodes the full polyphony of each grapheme. Central input for phonetic analysis.Source: Syllabary_CM / OSL
