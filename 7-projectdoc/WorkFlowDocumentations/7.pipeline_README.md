## Step 2: Oracc DCCLT Input

Unzip the Oracc JSON archives (https://oracc.museum.upenn.edu/json/) into `2-dataset/DataProfile/step2/dcclt/`:

The subfolder names below are a suggestion: `05_build_diri_lexical_list.py` finds `catalogue.json` (the one of `signlists` first) and every `corpusjson` folder below `step2/dcclt/` automatically.


| Oracc archive (as downloaded) | Put its content in |
|---|---|
| `dcclt-signlists` (`signlists/`) | `dcclt_full/dcclt/signlists/` (its `catalogue.json` is found there) |
| `dcclt` main project (`dcclt-5/corpusjson`, ~5,000 texts) | `dcclt2_full/dcclt-2/corpusjson/` |
| `dcclt-ebla` (`ebla/`) | `dcclt-ebla_full/dcclt-ebla/ebla/` |
| `dcclt-nineveh` (`nineveh/`) | `dcclt-niniveh_full/dcclt-niniveh/nineveh/` |

Expected: 233 Diri texts in the catalogue, 118 present, 115 with content, 4,084 lines. A later download may differ in a few rows because Oracc changes its editions (e.g. `{d}KU₃.GI` written `{d}KU₃-GI`); the check reports such rows as INFO. If fewer lines are found (for example 1,284 without the main `dcclt` project), the full list in `2-dataset/DataProfile/step2/` is kept and used, the lines found are written to `output/step2/diri_lexical_list_PARTIAL.csv`, and the check reports DIFF.

## Step 5: Corpus

The whole Old Babylonian corpus is parsed:      
`2-dataset/InputData/1.downloadCorpusATF/OBP_full/practiceOBP_all.atf`.      
16,906 tablets = 717 school + 16,189 practical.      
1,197 of them have only a header and no text lines, so 15,709 tablets give tokens.    
School and comparison corpora are separated later by the metadata (`is_school_text`, `genres`), never by file name:
`practiceOBP_all.atf` also contains the 717 school tablets of `OBP.atf`.

Reference numbers (run of 22 November 2026):     
2,267,828 tokens (81,150 compound, 1,985,845 atomic),    
3,465 unresolved,     
56,215 unreadable `x`;     
2,156,055 grapheme rows,     
2,153,364 with Unicode,     
662,336 LOGO.     
All reference numbers are kept in one place, the table `REFERENCE` at the top of `09_verify_pipeline.py`; they are changed there only after a run whose differences were checked and explained.

## Step 5.2: Function Of The Sign

`sign_type` (simple signs) and the column `sign_function` (all rows) are decided **by language and context**,
with exactly the rules of the gold standard: `08a_function_layer.py` uses `08b_goldlib.py` (copied unchanged from the gold package)
and the word-level steps of `build_gold.py` (without the manual word decisions). The letter-case rule is only a fallback
(176 tablets with unknown language; tokens that cannot be aligned): `function_rule = fallback:letter_case`, 26,474 rows.

Check on the 50 gold tablets, sign by sign, by function: Akkadian 98.6 %, Sumerian 94.6 % agreement with the gold standard
(LOGO share: Akkadian 19.9 % vs 20.5 % in the gold; Sumerian 61.0 % vs 56.4 %). 115 of the 118 Sumerian differences are
the manual word decisions of the gold. The letter-case rule alone would give 7.0 % LOGO in Sumerian texts.

## Step 6.0: Manual Check

`10_build_manual_check.py` builds the files P01–P15 from the outputs of Steps 1–5 and `osl.asl`: one CSV with the cases and one MD with the explanation per problem, plus `00_WORKFLOW.md`. Every row has corpus counts split into school / practical tablets and sites. Script 10 runs last, so after every run the lists reflect the current state of the pipeline.
