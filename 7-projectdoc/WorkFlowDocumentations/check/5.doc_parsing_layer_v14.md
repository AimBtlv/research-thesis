## Parsing: How ATF Text Becomes `atf_tokens.csv`, `grapheme.csv` and `warnings.csv`

This step takes real ATF transliteration text, together with the sign catalogue built in the Dataset stage (`allograph_all_v13.csv`, `compound_form_reading_table_v13.csv`), and produces a token-by-token record of the corpus.
Two scripts carry this out in sequence:
`07_parse_atf_to_tokens_v14.py` (= `1_transferTrLit_Sign_v14.py`) reads raw ATF and produces `atf_tokens.csv` (one row per token) plus one `{P-number}.txt` per tablet and `warnings.csv`.
`08_tokens_to_grapheme_v14.py` (= `2_txt_to_grapheme_v14.py`, with `08a_function_layer.py` and `08b_goldlib.py`) reads `atf_tokens.csv` together with CDLI's own catalogue metadata and expands every token into `grapheme.csv` (one row per actual sign occurrence, compounds exploded into their verified components) plus `warnings_grapheme.csv`.

```
practiceOBP_all.atf (16,906 tablets) ──► 07_parse_atf_to_tokens_v14.py ──► atf_tokens.csv + {P-number}.txt + warnings.csv

atf_tokens.csv + allOBP_metadata_16911.csv ──► 08_tokens_to_grapheme_v14.py ──► grapheme.csv + warnings_grapheme.csv
```

## Data Sources

| Source | Description |
|---|---|
| **allograph_all_v13.csv** (Dataset Step 4 output) | Sign catalogue: every atomic sign's own readings, and every compound's verified component list. |
| **compound_form_reading_table_v13.csv** (Dataset Step 3 output) | Compound whole-word readings, split into `attested_compound_dict` (real) and `inferred_compound_dict` (joined guess, never treated as fact). |
| **ATF corpus** `OBP_full/practiceOBP_all.atf` | The whole Old Babylonian corpus of CDLI in one file: **16,906 tablets** (717 school + 16,189 practical). 1,197 of them have only a header and no text lines (e.g. `$ (ATF deleted, = P117511)`), so **15,709 tablets** give tokens. Despite its name, the file also contains the 717 school tablets of `OBP.atf`. |
| **CDLI catalogue export** `OBP_full/allOBP_metadata_16911.csv` | One row per tablet (16,911 rows; 5 practical tablets have no ATF, `has_atf = 0`): `provenience`, `period`, `genres`, `languages`, CDLI's own uncertainty flags and `is_school_text`. Primary metadata source. |

**School and comparison corpora are separated by the metadata (`is_school_text`, `genres`), never by file name.** The earlier test folder `EDIII-OBP_School` (167 tablets) is no longer used: it was a trial version and not suitable for the diachronic analysis.

## Pipeline Overview

| Stage | Task | Note |
|---|---|---|
| **Stage 1** | Load `simple_dict`, `attested_compound_dict`, `inferred_compound_dict` from the Dataset catalogue | three normalised tables |
| **Stage 2** | Split the ATF file into tablets at its `&P…` lines; preprocess each line: ASCII-to-Unicode diacritics, `@`-modifier codes, damage and editorial marks, inline `($ ... $)` comments, `\|\|` apparatus lines, determinative extraction | one cleaned line, written to `{P-number}.txt` and used as the tokenizer's input |
| **Stage 3** | Tokenize each word | `atf_tokens.csv` |
| **Stage 4** | Expand compound tokens into their verified components, skip numeral / broken / unreadable / unresolved tokens, attach CDLI metadata | `grapheme.csv` |
| **Stage 5** | Collect every unresolved name, grouped by (name, provenance, period) | `warnings_grapheme.csv` |

## Step-By-Step Description

**1. Tablets And Line Preprocessing.**
A file may hold many tablets (`practiceOBP_all.atf`, `OBP.atf`): it is split at every `&P…` line, so that every tablet gets its own `p_number` (v14.1; before, a file was treated as one tablet).
ASCII diacritic conversion (`sz`→š, `s,` / `s'`→ṣ, `t,` / `t'`→ṭ), `@`-modifier table (`@x`→×, `@\`→`@t`, etc.), combining-diacritic folding (`g̃`→g, `ḫ`→h), and inline `($ ... $)` structural-comment removal.
`||`-apparatus lines: literary / composite editions cite parallel manuscript witnesses using lines like `>>A 122`, `||B 238`. These lines are skipped, so the line number of the other manuscript (`238`) does not leak through as sign content.

**2. Editorial Marks And Damage (v14).**
Signs in editorial brackets are **kept and labelled**, not deleted, in the column `editorial_state`:
| ATF | Meaning | `editorial_state` |
|---|---|---|
| `[ ]` | restored by the editor (the sign is broken away) | `restored` |
| `< >` | omitted by the scribe, supplied by the editor | `supplied` |
| `<< >>` | superfluous, written by the scribe, to be ignored | `superfluous` |

Stage 2 of the thesis decides what to count. The flags `#` (damaged), `?`, `!`, `*` are removed from the reading itself.

**3. Determinatives.**
`{d}`, `{ki}`, `{giš}` … are stripped before tokenisation and recorded in their own `determinative` column. A determinative with no separator on either side is replaced with a hyphen, not deleted outright, to avoid fusing neighbouring signs into a phantom sequence. Two determinatives sitting directly next to each other (`{disz}{d}suen-...`) used to leave an empty piece at the start of the word; empty pieces are now dropped (v14).

**4. Language Switch `_..._` (v13).**
The ATF underscore marks a stretch in the second language of the text. It is removed from the token and stored in the column `underscore_region`: `sumerogram` in an Akkadian text (`#atf: lang akk`, or no language line), `akkadian` in a Sumerian text.

**5. Numerals, Broken And Unreadable Signs.**
ATF numerals (`1(diš)`, `n(iku)`, `n+1(aš)`, `1/2`) and the collapsed ellipsis `…` (from `[...]`, meaning damaged or missing text) are not real signs, so they are recognised before any dictionary lookup and are never searched for in the sign dictionaries.
`x` and `(x)` (a sign that is present but unreadable) become `token_kind = unreadable` (v14), not the catalogue sign X.
This check happens at two levels: on the whole word, and separately on each piece inside a longer hyphenated word (`2(disz)-kam`, `…-ka-du`). Checking only the whole word would miss these cases.
The ellipsis check needed this second level for one more reason: the catalogue contains a real, unrelated sign named `xxx`, whose own attested reading is literally the text `…`. Without the check, every damaged-text marker would be matched to this sign.

**6. ATF Markup That Is Not A Word (v13–v14.2).**
Skipped, not reported as unresolved: the column separator `&`; the language shifts `%a`, `%s`, `%sux` …; the column separator `=` and the repetition mark `~` of bilingual lexical lists. Before this fix, 10 % of the tokens of lexical texts were reported as unresolved; after it, 0.82 %.

**7. Tokenisation.**
Space is always the outer boundary: a compound reading is never allowed to cross from one word into the next. Inside one word, hyphen and dot together mark the inner boundaries between individual signs.
When looking for a compound inside a word, the search always tries the longest possible span first, falling back to shorter spans only if nothing longer matches.
The first pass checks only real, attested readings (`attested_compound_dict`) across the entire word. Only after this pass is finished does the second pass check the remaining pieces against the weaker, guessed readings (`inferred_compound_dict`).
Sometimes a whole word has no hyphen or dot at all, and yet it is a complete, real compound reading by itself.

**8. Token Priority Correction.**
`simple_dict` is checked **before** `attested_dict` for any single piece: `u3` has both an ordinary atomic reading and an unrelated attested Diri compound reading, and the common syllable use must win by default.
The `source` field for a compound match is always one of `OSL`, `DIRI`, `OGSL`, `SYLLABARY_CM`, `QUALIFIER` (see 9), or empty.

**9. Qualified Readings `reading(SIGN)` (v14).**
In `kuₓ(DU)`, `gal!(GIR₃)` or `libₓ(|NI.UDU|)` the editor names the sign in brackets. The sign in brackets decides the identity (`source = QUALIFIER`); sign names written with ATF `x` are matched with the operator × (`|LAGABxTIL|` = `|LAGAB×TIL|`).

**10. Sign Identity Of Variants (v13).**
A catalogue variant that is a registered sign of its own (e.g. MAŠ₂, U+12227) is resolved under its own name instead of its parent's (KUN). A purely graphic variant (ASAL₂~a) keeps the parent's name, because ATF does not record the form of a sign.

**11. ş / ţ And ṣ / ṭ (v14.3).**
The syllabaries write the emphatic consonants with a cedilla (ş U+015F, ţ U+0163), OSL and CDLI ATF with a dot below (ṣ U+1E63, ṭ U+1E6D). The letters look alike, but for the computer they are different characters, so the catalogue reading `aţ` did not match the ATF reading `aṭ`. When the exact lookup finds nothing, a second index with one folded form is tried; the exact (OSL) reading always wins (ṭi₂ = TI₂ in OSL, but ţi2 = HI in the syllabary). Effect: 1,900 tokens resolved that were unresolved before (ṭe₄ 893, aṭ 709, ṭu₃ 270 …), all in agreement with OSL; no earlier decision changed.

**12. The `l.` / `r.` / `v.` / `s.` Prefixes.**
ATF sometimes uses short prefixes like `r.` or `v.` to reference another line (for example "see the reverse side"). These prefixes are not signs, so the dot inside them is never split as if it marked a compound. The rule covers a word starting with `l`, `r`, `v` or `s`, optionally followed by `e` and `?`, and then a dot (`r.`, `le.`, `v?.`). Only the prefix itself is cut off and kept as its own token; whatever comes after it is tokenised normally.

**13. Compound Expansion.**
Every token marked as a `compound` becomes several rows in `grapheme.csv`, one for each sign that makes up that compound. If a compound has three components, it becomes three rows, each with its own `component_position`.
The components are not worked out again here: they are taken directly from `allograph_all_v13.csv`, where this breakdown was established and checked earlier.

**14. Function Of The Sign: `sign_function` And `sign_type` (v14.4).**
The function of a sign (LOGO / SYLL / DET / NUM / UNCLEAR) is decided **by language and context, not by letter case**, with exactly the rules of the gold standard. `08a_function_layer.py` labels every tablet with the gold code (`08b_goldlib.py` = `goldlib.py` of the gold package, copied unchanged, plus the word-level steps of `build_gold.py`; the manual word overrides of the gold are not used) and transfers the result to the tokens of the pipeline by aligning their readings.

*Language of the tablet* (as in the gold): the `#atf: lang` line; else Sumerian for `#atf: use lexical`; else the CDLI `languages` field.

*Rules, in short:*
1. **Akkadian text:** signs inside `_..._` are Sumerian words (logograms; inside them the Sumerian rules below apply); signs outside are syllabic; Sumerian divine names after {d} (Suen, Enlil, Utu …) and the logographic first elements of personal names (dumu, lu₂, dingir, ARAD …) are LOGO; meš is a plural marker (DET).
2. **Sumerian text:** a one-sign word is LOGO (unless it is a pure grammatical element); in a longer word the verbal prefixes are SYLL, the first sign after them (the root) is LOGO, further lexical signs are LOGO, suffixes and phonetic complements are SYLL; Akkadian words written syllabically inside a Sumerian text (names, loanwords: q, ṣ, ṭ, w, mimation …) are SYLL; `_..._` in a Sumerian text is Akkadian (SYLL).
3. Glosses are SYLL; classifier words at the head of a lexical entry (giš, na₄, kuš …) are DET.
4. **Fallback:** if the language of the tablet is unknown (176 tablets), or a token cannot be aligned, the old letter-case rule is used (capital → LOGO, lowercase → SYLL; `function_rule = fallback:letter_case`, 26,529 rows, 1.2 %).

*Columns:* `sign_function` (every row, compound components included), `function_rule` (which rule decided), `function_needs_check` (1 = uncertain, e.g. Akkadian word inside a Sumerian text), `line_ref` (side:column:line, from the same alignment).
*`sign_type`* keeps its structural meaning: a compound is always `COMPOUND`; for a simple sign it takes the value of `sign_function` (LOGO / SYLL, rarely DET / UNCLEAR); a token without letters (the word divider `/`) is `UNKNOWN` (71 rows).

**Check on the 50 gold-standard tablets** (same tablets, sign by sign):
| Language of the text | Agreement with the gold | LOGO in the gold | LOGO in grapheme.csv v14.4 | LOGO with the old letter-case rule |
|---|---|---|---|---|
| Akkadian | **98.6 %** | 20.5 % | 19.9 % | 19.6 % |
| Sumerian | **94.6 %** | 56.4 % | 61.0 % | **7.0 %** |

115 of the 118 Sumerian differences are words corrected by hand in the gold (`word_overrides.csv`), which the pipeline deliberately does not use; the remaining 3 come from compound spans (the function of the first sign is taken). ⚠️ The gold standard itself is not yet verified by a human (Step 6.8), so these numbers measure the transfer of the rules, not yet their true accuracy.

Numerals, broken, unreadable and unresolved tokens are left out of `grapheme.csv`:
`numeral`, `broken`, `unreadable` are kept in `atf_tokens.csv`;
`unresolved` are kept in `atf_tokens.csv`, `warnings.csv` and `warnings_grapheme.csv`.

**15. Metadata From CDLI's Own Catalogue Export.**
Metadata for each tablet is read directly from CDLI's catalogue export (`allOBP_metadata_16911.csv`, one row per tablet; a folder of single `artifacts_{artifact_id}.csv` files is still accepted).
CDLI sometimes marks its own data as uncertain, for example when it is not fully sure about a tablet's genre, period, or findspot. These markers (`genre_uncertain`, `period_uncertain`, `provenience_uncertain`) are copied exactly as CDLI recorded them, never decided or calculated here. The same applies to `is_school_text`, the flag CDLI uses to mark a tablet as a school exercise.
Two CDLI fields contain two pieces of information joined together, so each is split into two columns:
the `period` field, e.g. `"ED IIIa (ca. 2600-2500 BC)"`, into `period_index` (`"ED IIIa"`) and `period_dates` (`"ca. 2600-2500 BC"`);
the `provenience` field, e.g. `"Shuruppak (mod. Fara)"`, into `provenance` (`"Shuruppak"`, the ancient name) and `modern` (`"Fara"`, the modern name).

**16. Warnings File.**
Unresolved names are grouped in `warnings_grapheme.csv` with the place and period they come from, so the same word failing in two different periods produces two separate rows.
Each row shows the unresolved name, where it comes from (provenance and period), how many times exactly this combination occurred, and one real example `word_id` (to trace the row back to one occurrence in the source text).

## Output: atf_tokens.csv

One row per token occurrence in the corpus, before compound expansion. One file for the whole corpus (not one per tablet).
**How It Is Built**
Each line is cleaned once (diacritics, ATF markers, damage flags) and that same cleaned line is used both for the `.txt` file and for splitting into tokens. Tokens are split by space first, then by hyphen or dot within each word, always trying the longest match first and falling back to shorter spans only when nothing longer is found. Real attested compound readings are always checked before guessed compounds.

**Result (whole OB corpus, parser v14.3):** 2,267,576 tokens from 15,709 tablets.
| `token_kind` | Tokens | Share |
|---|---|---|
| atomic | 1,986,188 | 87.6 % |
| compound | 80,525 | 3.6 % |
| numeral | 79,465 | 3.5 % |
| broken | 61,688 | 2.7 % |
| unreadable | 56,215 | 2.5 % |
| unresolved | 3,495 | 0.15 % |

**Unresolved share by corpus** (the open question whether different shares distort the comparison): school 0.32 %, literary 0.23 %, administrative 0.10 %, legal 0.06 %, letters 0.05 %, lexical 0.82 %. The differences are small; for lexical texts they should be mentioned.

### Columns

●	**`p_number`** tablet identifier, from the ATF `&`-line.
●	**`line_num`** transliteration line label, as given in the ATF (e.g. `1'.`). ⚠️ The side of the tablet (obverse / reverse) is not stored, so `1.` on the obverse and `1.` on the reverse have the same label.
●	**`word_id`** `{p_number}_{sequential number}`; one id per ATF word, shared by all its tokens.
●	**`raw_atf_token`** the exact source text for this token (single sign or whole compound span), case untouched.
●	**`resolved_name`** canonical `sign_name` (atomic) or `compound_form` (compound).
●	**`token_kind`** `atomic` / `compound` / `numeral` / `broken` / `unreadable` / `unresolved`.
●	**`confidence`** `attested` / `inferred`; empty for numeral, broken, unreadable or unresolved.
●	**`source`** `OSL` / `DIRI` / `OGSL` / `SYLLABARY_CM` for attested compounds, `QUALIFIER` for `reading(SIGN)`, empty otherwise.
●	**`determinative`** semicolon-separated determinatives stripped from this word, empty if none.
●	**`underscore_region`** *(v13)* `sumerogram` / `akkadian` / empty (see 4).
●	**`editorial_state`** *(v14)* `restored` / `supplied` / `superfluous` (combinations possible, e.g. `restored,supplied`) / empty (see 2).

## Output: grapheme.csv

One row per **actual sign occurrence**: a compound token becomes N rows, one per verified component, not one opaque row.
**How It Is Built**
The script reads `allograph_all_v13.csv` once at the start and builds two lookups from it: one for atomic signs (from ATF name to Unicode code and glyph), and one for compounds (from ATF name to the verified list of its components, each with its own position, code, and glyph).

It then reads `atf_tokens.csv` one token at a time and decides what to do based on its kind:

- a **compound** token becomes several rows (one for each of its components). All these rows share the same compound name and the same original reading, but each has its own Unicode code, glyph, and position;
- an **atomic** token becomes exactly one row;
- a **numeral**, a **broken**-text marker, an **unreadable** sign or an **unresolved** token becomes no row here (none of these is an identified sign). They are not lost: they stay in `atf_tokens.csv`, and unresolved names also in `warnings_grapheme.csv`.

For every row, `sign_function` and `sign_type` are decided by the rules in Step 14 (by language and context), and every row is stamped with the metadata of its tablet from CDLI's catalogue (not guessed from the text).

**Result:** 2,157,401 rows (1,986,188 simple + 171,213 compound-component rows); 2,154,856 with a Unicode code. `sign_type`: SYLL 1,313,176, LOGO 663,102, COMPOUND 171,213, DET 9,536, UNCLEAR 303, UNKNOWN 71 (with the old letter-case rule: LOGO 317,095). 1,905 rows have no `sign_function`: 1,834 compound components that could not be aligned and 71 word dividers. `editorial_state`: restored 116,923, supplied 3,127, superfluous 601.

⚠️ 2,545 rows have no Unicode code. They are readings resolved to a name that comes only from the historical syllabaries and is written like a compound (`SIPA` 1,006, `KA.AN.RA` 537, `AŠ2.A.AN` 428, `IDIGNA` 205 …), so the parser takes them as one simple sign without a code point. To be checked: these names should probably point to the corresponding OSL compounds (e.g. sipa = |PA.LU|).

### Columns

●	**`unicode_id`** for a compound row, the code of this specific component, not of the compound as a whole.
●	**`sign_grapheme`** glyph of the sign (or of the component).
●	**`sign_trlitScien`** canonical sign name, or the whole compound's name repeated across all its component rows.
●	**`sign_phonetic`** the original ATF reading (`raw_atf_token`, passed through unchanged).
●	**`sign_translation`** reserved, not populated automatically.
●	**`sign_type`** `COMPOUND` for compounds; for simple signs the value of `sign_function` (`LOGO` / `SYLL`, rarely `DET` / `UNCLEAR`); `UNKNOWN` for tokens without letters (see Step 14; not the same as Type_1/2/3 in the catalogue).
●	**`is_compound`** `SIMPLE` / `COMPOUND`.
●	**`component_position`** 1-based position within the compound; empty for simple signs.
●	**`word_id`** traces back to `atf_tokens.csv` (and through it to `line_num`).
●	**`confidence`** / **`source`** carried through from `atf_tokens.csv` unchanged.
●	**`artifact_id`, `corpus_id`, `genre_name`, `provenance`, `modern`, `archaeological_context`, `period_index`, `period_dates`, `languages`** from CDLI's catalogue export.
●	**`is_school_text`, `genre_uncertain`, `period_uncertain`, `provenience_uncertain`** CDLI's own flags, copied unchanged.
●	**`editorial_state`** *(v14)* copied from `atf_tokens.csv`.
●	**`sign_function`** *(v14.4)* `LOGO` / `SYLL` / `DET` / `NUM` / `UNCLEAR`, by language and context (Step 14), for every row.
●	**`function_rule`** *(v14.4)* the rule that decided, e.g. `sux:root`, `akk:inside_underscore|…`, `fallback:letter_case`.
●	**`function_needs_check`** *(v14.4)* 1 if the decision is uncertain.
●	**`line_ref`** *(v14.4)* side:column:line of the tablet (e.g. `obv::3`, `rev:ii:5`).

**Not yet in grapheme.csv** (needed for the formula demo): an explicit sign order (`sign_index`, `reading_unit_id`) and a flag for readings that belong to several signs (`n_candidates`, `alt_candidates`). Until then the order of the rows in the file must not be changed. (`line_ref` was added in v14.4.)

## warnings.csv / warnings_grapheme.csv

Two separate warnings files, one per script, deliberately not merged:

●	**`warnings.csv`** (script `07_parse_atf_to_tokens_v14.py`) normalised tokens that matched nothing in any of the three dictionaries at the tokenisation stage. Columns: `normalized_token`, `count`. 1,259 distinct tokens (most frequent: tur3 357, (…) 125, ginx 109, gilgames2 94).
●	**`warnings_grapheme.csv`** (script `08_tokens_to_grapheme_v14.py`) unresolved names grouped by place and period. Columns: `word_id`, `unresolved_name`, `sign_type`, `provenance`, `period_index`, `count`. 1,525 rows.

They are kept separate because they diagnose two different failure points: a gap in the phonetic dictionaries (script 06) and the distribution of the remaining gaps by place and period (script 07).

## Reproducibility

Both scripts run in the VS Code task "RUN ALL" (about 1–2 minutes for the whole corpus). `09_verify_pipeline.py` checks the reference numbers: 15,709 tablets, 2,267,576 tokens, 3,495 unresolved, 56,215 unreadable, 2,157,401 grapheme rows, 2,154,856 with Unicode, 663,102 LOGO, 26,529 rows labelled by the letter-case fallback. Step 5.2 takes about 2 minutes. The output files are large (`atf_tokens.csv` about 120 MB, `grapheme.csv` about 330 MB) and are not stored in Git.
