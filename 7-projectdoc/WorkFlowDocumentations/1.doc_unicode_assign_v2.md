##  1. How  Assigned Unicode ID and Phonetic Versions?

This step establishes a catalogue that assigns to every cuneiform sign in Unicode its unique identifier and its full range of phonetic transliteration values.

The goal is to create a single reference table as the lookup layer for all subsequent corpus parsing. When an ATF text contains a token such as 'sila₃' or lamma(GURUŠ), the pipeline must be able to answer two questions:
- Which Unicode sign does this token refer to?
- What is the full set of phonetic values this sign can carry?

**The first stage of the pipeline is to assign: Unicode ID + Phonetic Version table.**

## Data Sources

|Source	|Description|
|----|----|
|**Unicode cuneiform blocks** 1_unicodeSigns.csv|Complete list of **1,234** cuneiform code points (U+12000–U+12543) as defined by the Unicode Consortium, from three blocks: Cuneiform (U+12000–U+123FF, 922 signs), Cuneiform Numbers and Punctuation (U+12400–U+1247F, 116 signs), Early Dynastic Cuneiform (U+12480–U+1254F, 196 signs). Each entry carries the code point, the cuneiform glyph, and a plain-text transliteration label derived from the Unicode character name.|
|**Syllabary CM** syllabary_CM.txt |Sign list compiled by Professor Massimo Maiocchi. Maps phonetic ATF readings to scientific sign names (e.g. sila₃ to SILA₃). Covers standard cuneiform periods.|
|**Uruk Archaic Syllabary** syllabary_uruk2.txt|Sign list for the proto-cuneiform Uruk IV–III period (3400–3000 BCE). |
|**Additional Signs** additional_signs.txt|Supplementary mapping file for rare, compound, or non-standard sign forms encountered in CDLI corpora that are absent from the main syllabary.|
|**ORACC Sign List** osl.asl (6_osl.asl)|Machine-readable version of the ORACC Sign List (OSL), the current standard scientific catalogue of cuneiform signs. ASL format encodes sign names (@sign), sign forms (@form), Unicode IDs (@list U+), glyphs (@ucun), and all attested phonetic values (@v). Our version has 3,309 @sign blocks; 1,215 of them carry a Unicode ID.|

## Pipeline Overview

The pipeline follows a sequential strategy, processing the Unicode sign list in two passes.
1. The first pass matches signs to the professor's syllabary.
2. The second pass enriches the remaining unmatched signs from the ORACC Sign List.

---
Both outputs are merged into a unified table of **1,234** entries.

|Stage|	Input|	Output|
|---|---|---|
**Stage A**|1_unicodeSigns.csv + syllabary_CM.txt, additional_signs.txt, syllabary_uruk2.txt|3_matched_signs_full.csv (791) + 4_unmatched_for_review.csv (443)|
**Stage B**|4_unmatched_for_review.csv (443) + osl.asl|5_restUnicodeSigns.csv (443): 424 with a sign name (245 of them also with readings) + 19 without a sign name*|
**Stage C**|3_matched_signs_full.csv (791) + 5_restUnicodeSigns.csv (443)|7_unicodePhoneticVersion_full.csv: 1,234 signs|

*Of the 19 signs without a sign name, 16 appear in osl.asl only as @form (a form of another sign), 2 only under a deprecated @sign- entry, and 1 (U+1243A) is absent from osl.asl.

## Step-by-Step Description
### 1. Build the Syllabary (Syllabary_CM.csv)
Three source files were merged into a single, unified syllabary:    
●	**syllabary_CM.txt** the main phonetic mapping compiled by Professor Massimo Maiocchi: 19,274 entries.    
●	**syllabary_uruk2.txt** archaic Uruk-period sign names: 2,212 entries.    
●	**additional_signs.txt** supplementary entries for rare or compound forms: 65 entries.   

Each line in the merged file follows the format: phonetic_reading to SIGN_NAME, with the column source (CM / URUK2 / ADDITIONAL). Of the 21,551 raw entries, 91 duplicates were removed (90 from URUK2, 1 from ADDITIONAL), which gives **21,460** entries.

**Output: Syllabary_CM.csv** (21,460 rows: CM 19,274, URUK2 2,122, ADDITIONAL 64).

**Script:** 01_build_syllabary_CM.py.

### 2. Download and Prepare the Unicode Sign List
The complete list of cuneiform Unicode code points was obtained from the Unicode Consortium's three cuneiform blocks (U+12000–U+12543).    
**Links**: https://www.unicode.org/charts/PDF/U12000.pdf, https://www.unicode.org/charts/PDF/U12400.pdf, https://www.unicode.org/charts/PDF/U12480.pdf    
**Resulting** in **1,234** signs.

**Each record contains:**  
●	**unicode_id** the code point (e.g. U+12000).     
●	**sign_grapheme** the rendered cuneiform character (e.g. 𒀀).     
●	**transliteration** the Unicode character name converted to transliteration form (e.g. "a", "a × bad").

**Output: `1_unicodeSigns.csv`**     
This file becomes the left-hand side of all subsequent joins and defines the target set: every sign in the final catalogue must have a Unicode ID.

### 3. First Join: Unicode List × Syllabary (Stage A)
The Unicode sign list was joined against the three syllabary files (the same sources as Syllabary_CM.csv, read in the order CM, ADDITIONAL, URUK2).

Unicode names and syllabary entries are written in different conventions (Unicode: "ash₂", "a × gan₂ tenu". Syllabary: "AŠ2", "A×GAN2@t"). Both sides are therefore brought to one normalised form before matching:    
●	subscripts become digits, × becomes X;    
●	the Unicode modifier words become ATF modifiers: GUNU → @G, TENU → @T;     
●	the English spelling SH becomes Š (ASH → AŠ, GISH → GIŠ, SHESH → ŠEŠ);     
●	THREE becomes X3, the dots of DAG.KISIM5 and NUNUZ. are restored;      
●	the purely descriptive words OPPOSING and SQUARED are removed; spaces are removed.     

A Unicode sign is matched first by the normalised **sign name** of the syllabary, then by a normalised **reading**. If several candidates fit, the first one found is taken.

The join produces two outputs:       
●	**`3_matched_signs_full.csv` (791 signs)** signs found in both the Unicode list and the syllabary. Each matched sign receives its syllabarySign (scientific name) and PhoneticsVersion (all readings of that sign in the syllabary, separated by " | ").     
●	**4_unmatched_for_review.csv (443 signs)** signs present in the Unicode list but absent from the syllabary. These are mainly signs with a purely descriptive Unicode name: stacked signs (AN / AN), crossing signs (BU crossing BU), the modifiers ZIDA and KABA, and rare compounds. The column translit_normalized shows the form that was searched for.

**Output:**
|Output file|Count|Status after Stage A|
|---|---|---|
|`3_matched_signs_full.csv`|791|Complete: unicode_id + phonetic values assigned|
|`4_unmatched_for_review.csv`|443|Partial: unicode_id only, no phonetic values yet|
|Total|1,234|Covers the full Unicode cuneiform blocks|

**Script:** `01b_join_unicode_syllabary_CM.py`

**Known limitations** (kept unchanged so that the result stays reproducible):   
●	OPPOSING and SQUARED are removed, so "an + naga opposing an + naga" and "an + naga     squared" both become AN+NAGA and can be matched to the same syllabary sign. Such matches should be checked manually.     
●	When several syllabary signs fit, the first one is taken without a flag.

### 4. Second Join: Unmatched Signs × OSL (Stage B)
The 443 unmatched signs were processed against the ORACC Sign List (osl.asl). The OSL file is structured into @sign blocks, each identified by a @list U+ tag that links the sign to its Unicode code point.

For each unmatched sign, the parser:    
●	Searched the OSL for a @sign block whose @list U+ matches the sign's unicode_id.    
●	Extracted the scientific sign name from the @sign line to the column syllabarySign.    
●	Collected all @v (phonetic value) entries in that block to the column PhoneticsVersion (separated by " | ").

**Output: 5_restUnicodeSigns.csv**.
|Sign|Count|Description|
|---|---|---|
|Found in OSL, with sign name and readings|245|-|
|Found in OSL, sign name only|179|The @sign block has no @v values: 151 Early Dynastic signs, 20 signs of the main Cuneiform block, 8 numerals or punctuation signs.|
|Not found as a main @sign in OSL|19|16 appear only as @form (a graphic form inside another @sign block; the reading is inherited from the parent sign); 2 appear only under a deprecated @sign- entry (U+122AA \|SAL.LAGAB×AŠ₂\|, U+12376 \|DUB×ŠE\|); 1 is absent from osl.asl (U+1243A).|
|Total|443|Phonetic fields left empty where unavailable|

**Script:** 03_build_rest_unicode_signs.py.

### 5. Merge: Final Catalogue (Stage C)
The two output files from Stages A and B were joined into a single unified catalogue, in the order of 1_unicodeSigns.csv:
|Source file|	Records|	Notes|
|---|---|---|
|3_matched_signs_full.csv|791|Full phonetic coverage from the syllabary|
|5_restUnicodeSigns.csv|443|Sign names from OSL (424); readings from OSL @v (245)|
|Total|1,234|Covers the complete Unicode cuneiform blocks|

**Output: 7_unicodePhoneticVersion_full.csv**

**Script:** 04_join_matched_rest_signs.py 

## Output Description
Output: 7_unicodePhoneticVersion_full.csv
Total signs in the Unicode cuneiform blocks: **1,234**.
|Coverage|Signs|
|---|---|
|with a scientific sign name|1,215|
|with at least one reading|1,036 (791 from the syllabary + 245 from OSL)|
|without a sign name|19 (see Stage B)|

The PhoneticsVersion column deliberately records all attested readings for each sign, not only the most common one.

All records share the same schema:
- **unicode_id** - Code point in U+XXXXX format. Primary key. Unique per sign. Source: Unicode Consortium
- **sign_grapheme** - Rendered cuneiform character. One character for simple signs, and a sequence for compound signs that lack a unified code point. Source: Unicode Consortium
- **unicodeTrLit** - Human-readable transliteration of the Unicode character name. Describes the graphic composition of the sign (e.g. "a × bad" for A×BAD). Source: Unicode Consortium
- **syllabarySign** - Scientific sign name as used in Assyriology (e.g. A, SILA₃, |AN.KI|). Standard identifier used in sign lists and cited in publications. Source: Syllabary_CM / OSL
- **PhoneticsVersion** - All attested phonetic readings of the sign, separated by " | ". Encodes the full polyphony of each grapheme. Central input for phonetic analysis. Source: Syllabary_CM / OSL

**Next step:** the gaps left here (signs without readings) are filled in the full sign catalogue (Steps 3–4): readings from OSL @v are added only where the catalogue has none (490 rows), and every disagreement between OSL and the catalogue is recorded in a separate file (748 conflicts) instead of being overwritten.
